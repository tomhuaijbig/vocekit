# vocekit 项目迭代复盘

本文档用于记录本项目从需求提出到当前版本的主要变动、优化迭代、返工原因和经验教训。  
以后如果继续用 AI 开发 Qt 软件，可以把这份文档交给新的 AI 或开发者，让对方快速理解哪些地方容易做错。

## 一、项目目标

本项目是一个基于 Qt 5.9 的 Windows 桌面语音助手，当前项目名为 `vocekit`。

核心方向：

- 后台托盘常驻，不占用日常桌面窗口。
- 使用全局快捷键触发听写、翻译、问答和自定义功能。
- 支持语音转文字、选中文本翻译、基于选中文本问答。
- 支持录音保存、历史记录、提示词编辑、接口密钥配置。
- 参考同类语音输入软件 的交互思路，但不复制品牌、图标、文案和资源。
- 以后可以打包给别人测试，不能泄露本机 API 密钥、录音和历史。

## 二、需求和优化迭代记录

### 1. 初始功能需求

最开始提出的功能包括：

- 使用 Qt 开发 Windows 桌面应用。
- 可以调用 DeepSeek API。
- 可以调用百度 API。
- 密钥放在本地文本中，软件需要读取。
- 日常运行时不占桌面窗口，可以后台运行。
- 使用快捷键启动功能。
- 至少支持语音转文字、翻译、问答、录音、提示词管理。

后续调整：

- 不再依赖 `1.txt` 读取密钥。
- 改为在软件“设置 -> 接口”中填写密钥。
- `config/secrets.json` 保存本地密钥，但测试包只放空白配置。

### 2. 参考软件风格方案

用户要求“参考同类语音输入软件”。最终确定的方向是：

- 托盘常驻。
- 全局快捷键。
- 浮动状态条。
- 主界面 Hub。
- 历史记录。
- 自动写入当前输入框。
- 结果小框。

明确边界：

- 只模仿交互和功能方向。
- 不复制参考软件的品牌、图标、文案或视觉资产。

### 3. 第一版 UI 预览

先实现了启动后的 UI 原型，重点是让用户看到整体结构：

- 左侧导航栏。
- 主界面标题。
- 听写、翻译、问答三张功能卡片。
- 最近记录区域。
- 当前状态区域。
- 底部浮动条预览。

后续根据截图反馈多次调整：

- 品牌名从早期英文样式改成“语音助手”。
- 尽量少用英文，必要英文用括号说明。
- 主界面标题改成中文。
- 功能名从 Dictate、Translate、Ask anything 改成听写、翻译、问答。
- 修复卡片中文字裁剪问题。

### 4. 快捷键自定义

用户要求快捷键必须可自定义。

实现方向：

- 默认快捷键：
  - 听写：`Ctrl + Alt + Space`
  - 翻译：`Ctrl + Alt + T`
  - 问答：`Ctrl + Alt + Q`
  - 打开主界面：`Ctrl + Alt + S`
- 设置页增加快捷键修改入口。
- 使用 Windows `RegisterHotKey` 注册全局快捷键。
- 检查快捷键冲突。

后续补充：

- 自定义功能也可以设置独立快捷键。
- 快捷键显示在主页功能卡片上。

### 5. 中文化和上下文菜单

用户多次反馈界面中仍有英文。

已处理：

- 主要 UI 文案改为中文。
- 设置页、历史记录、提示词、接口页等文案改为中文。
- 文本框右键菜单从英文改为中文。
- 保留快捷键显示，例如“复制 Ctrl+C”，但菜单动作名称使用中文。

经验：

- Qt 自带 `qt_zh_CN.qm` 不能保证所有文本框右键菜单都翻译。
- 最后增加了全局事件过滤器，对 `Undo / Redo / Cut / Copy / Paste / Delete / Select All` 做中文替换。

### 6. 自定义功能

用户要求左侧增加“自定义功能”，并且自定义功能要和听写、翻译、问答并列。

实现内容：

- 左侧导航增加“自定义功能”。
- 主页上方功能卡片支持显示自定义功能。
- 可以新增多个自定义功能。
- 每个自定义功能有：
  - 名称。
  - 快捷键。
  - 模型。
  - 输入方式。
  - 展现方式。
  - 浮动条显示时间。
  - 结果小框显示时间。
  - 独立提示词。
- 自定义功能会同步出现在提示词选择列表和历史记录筛选中。

### 7. 模型选择

用户要求每个功能可以选择模型，先只支持 DeepSeek，后来要求增加 OpenAI 和 Claude。

已实现：

- 听写、翻译、问答、自定义功能都能独立选择模型。
- 支持 DeepSeek。
- 支持 OpenAI 模型项。
- 支持 Claude 模型项。
- 模型下拉框只显示官方模型名，不再写“最顶级”“推荐”等主观描述。

重要反馈：

- 用户明确要求 Claude 不使用太老的模型。
- 用户要求去掉 `claude-haiku-4-5-20251001` 这种日期后缀，显示为 `claude-haiku-4-5`。

### 8. 接口密钥配置

最初密钥来自本地文本文件。用户后来要求可以在软件里填写 API。

已实现：

- 设置页增加“接口”页。
- 语音识别接口和大模型接口分区。
- 语音识别接口包括：
  - 当前语音识别服务。
  - 百度 API Key。
  - 百度 Secret Key。
  - 百度 AppID。
  - 讯飞 AppID。
  - 讯飞 API Key。
  - 讯飞 API Secret。
- 大模型接口包括：
  - DeepSeek API Key。
  - OpenAI API Key。
  - Claude API Key。
- 密钥输入框默认隐藏，可点击显示。

后续修正：

- 删除“从文本重新读取”按钮。
- 删除从 `1.txt` 自动补充旧密钥的兼容能力。
- 接口页关闭时自动保存。
- 接口页底部“保存接口配置”改成固定按钮，不再要求滚动到最底部。

### 9. 语音识别服务

最初只计划百度语音识别。后来用户提供讯飞文档，要求接入讯飞。

已实现：

- 百度语音识别。
- 讯飞语音听写。
- 设置中可以选择当前语音识别服务。
- 当前状态区域显示当前语音识别服务。

返工点：

- 用户选择讯飞后，曾经仍提示缺少百度密钥。
- 原因不是识别分支本身，而是接口页关闭时没有保存选择，程序仍沿用旧的百度配置。
- 修正后，程序在开始录音前重新读取配置，并只校验当前选择的语音服务。

### 10. 网络代理

用户发现 DeepSeek 调用慢或失败，与 VPN 和系统代理有关。

已实现：

- 默认不走系统代理，强制直连。
- 设置中可以打开“使用系统代理”。
- 当前状态中显示网络代理状态。

设计结论：

- 对国内服务和 DeepSeek，默认直连更符合当前使用场景。
- 只有用户明确需要时才走代理。

### 11. 听写性能

用户反馈大模型调用阶段慢。

调整：

- 听写默认使用快速模式。
- 百度或讯飞识别完成后可以直接输出，不强制等待大模型整理。
- 如果需要模型整理，可以在设置中开启“听写整理”。

目的：

- 日常听写优先快。
- 需要润色时再调用模型。

### 12. 翻译逻辑

翻译功能经历了多次澄清。

最初理解：

- 有选中文本时翻译选中文本。
- 没有选中文本时录音并翻译语音内容。

用户后续明确：

- 翻译就是读取鼠标拖选的文字进行翻译。
- 不是语音翻译用户说的话。
- “选中”指鼠标左键拖选文本，不要立即模拟 `Ctrl+C`。
- 不要复制，不要询问剪贴板确认复制成功。

调整方向：

- 翻译默认使用选中文字。
- 通过系统选区读取，不再把“复制到剪贴板”当成默认逻辑。
- 功能方式中允许每个功能独立选择是否使用选中文字、是否使用语音输入。

用户要求把自动写入和结果小框做成可选项。

已实现：

后续补充：

- 每个功能可以单独设置浮动条显示时间。
- 每个功能可以单独设置结果小框显示时间。

- 结果小框和浮动条时间可配置。

后续安全修正：

### 19. 设置页滚动和布局

用户多次反馈设置页和主页在小窗口、全屏下的布局问题。

处理过的问题：

- 设置页内容太挤，需要支持鼠标滚轮滚动。
- 不能把整个页面做成过大的滚动区域，只应该让内容部分滚动。
- 主页上方功能卡片区域在全屏时太小，明明有空地却显示不全。
- 小窗口下功能卡片文字裁剪。
- 设置页接口按钮在滚动底部，用户容易找不到。

当前原则：

- 长内容区域可以滚动。
- 常用保存按钮应固定在可见位置。
- 不要把用户必须点击的按钮藏在滚动区域底部。
- 小窗口也要保证重要文字和按钮不被裁剪。

## 三、我理解不到位和返工的地方

这一部分专门记录开发过程中我没有一次理解到位、设计不科学或需要用户多次纠正的地方。

### 1. 没有一开始就把“保存按钮可见性”当成关键交互

问题：

- 接口页的“保存接口配置”最初放在滚动内容底部。
- 用户填写密钥后必须滑到最底下才能保存。
- 对第一次使用的人来说，不知道底下还有保存按钮。

造成的后果：

- 用户以为保存了，实际没有保存。
- 语音识别服务选择可能仍停留在旧配置。
- 后续出现“选择讯飞却提示缺少百度密钥”的误导性错误。

以后应避免：

- 长设置页必须把保存按钮固定在可见区域。
- 核心操作按钮不能放在滚动区域最底部。

### 2. 对“置顶提示框”的尺度把握错误

问题：

- 用户要求错误提示框不要在最底层。
- 我一开始改成持续置顶，并使用 `HWND_TOPMOST`。
- 这导致火绒认为是高危危险操作。

正确理解：

- 用户需要的是“弹出来时能看到”。
- 不是“永远压在其他窗口上”。
- 正确行为是前台提醒一次，用户点击其他窗口后可以被遮住。

以后应避免：

- 不要轻易使用持续置顶。
- 不要滥用 `HWND_TOPMOST`。
- 对后台软件、快捷键软件、剪贴板软件尤其要注意安全软件误报。

### 3. 翻译功能最初没有准确理解“选中文字”

问题：

- 我最初把翻译设计成：有选中文本就翻译选中文本，没有选中文本就录音翻译语音。
- 用户实际要的是鼠标左键拖选文字后翻译。
- 用户明确不要立即模拟 `Ctrl+C`。
- 用户明确不要复制剪贴板。

正确理解：

- 翻译模式默认应处理鼠标拖选的文字。
- 语音输入是否参与应由功能方式设置决定。
- 不能把“复制到剪贴板”当成读取选区的默认动作。

以后应避免：

- “选中”不等于“复制”。
- 自动化读取文本前必须确认是否允许使用剪贴板。

### 4. 没有一开始就把功能输入方式做成独立设置

问题：

- 最初听写、翻译、问答的输入方式是固定逻辑。
- 用户后来要求听写、翻译、问答、自定义都可以自主选择：
  - 是否读取选中文字。
  - 是否调用语音。
  - 自动写入还是结果小框。

正确理解：

- 每个功能都应有独立配置。
- 不同功能不能共用一个笼统行为。

以后应避免：

- 不要把多个功能的行为硬编码在一起。
- 对快捷键工具，功能行为必须可单独配置。

### 5. 没有及时考虑小窗口和中文字体裁剪

问题：

- 多个地方出现文字被裁剪：
  - 主页功能卡片小字。
  - 历史记录文字。
  - 设置页提示词底部按钮。
- 按钮高度和卡片高度在中文字体下不够。

正确理解：

- Qt 5.9 的字体渲染和样式 padding 容易导致中文底部裁剪。
- 固定高度按钮不能只按英文视觉估算。

以后应避免：

- 中文按钮建议至少 40px 到 42px 高。
- 卡片文字要给足行高和高度。
- 小窗口和全屏都要检查。

### 6. 没有一开始就做好历史记录性能

问题：

- 历史记录打开时会卡顿。
- “全部”页尤其容易卡。

原因：

- 历史记录越来越多后，一次性读取和渲染会拖慢 UI。

正确处理：

- 缓存历史。
- 首次只加载一部分。
- 提供“加载更多”。
- 设置中允许调整首次加载数量和加载更多数量。

以后应避免：

- 不要把历史记录当成少量数据处理。
- 本地文件历史也要考虑分页和缓存。

### 7. 没有一开始就把测试包和源码目录分开

问题：

- 开发目录里有源码、密钥、录音、历史和构建输出。
- 直接发文件夹很容易泄露个人数据。

正确处理：

- 生成独立 `dist/vocekit-test`。
- 测试包只包含运行所需文件。
- 使用空白密钥配置。
- 排除录音、历史、源码和中间文件。

以后应避免：

- 不要手动挑文件发送。
- 必须用脚本生成测试包。
- 打包后要检查是否含密钥。

### 8. 对接口配置保存时机判断不够严谨

问题：

- 一开始只有点击“保存接口配置”才保存。
- 用户关闭设置窗口后以为保存了。

正确处理：

- 关闭设置窗口也自动保存接口配置。
- 但仍保留显式保存按钮。
- 显式保存按钮应始终可见。

以后应避免：

- 设置页关闭行为要符合用户直觉。
- 如果用户刚刚填写了表单，关闭窗口不应悄悄丢失。

### 9. 对网络代理问题一开始判断不够直接

问题：

- 大模型调用慢时，最初容易从模型或代码角度排查。
- 用户后来判断是 VPN / 系统代理导致 DeepSeek 慢或连不上。

正确处理：

- 默认直连。
- 提供“使用系统代理”开关。
- 当前状态显示代理模式。

以后应避免：

- 国内 API、国外 VPN、系统代理同时存在时，要优先检查代理。
- 网络请求慢不一定是模型慢。

### 10. 对 Qt 运行库依赖变化没有提前处理

问题：

- 接入讯飞 WebSocket 后，程序缺少 `Qt5WebSockets.dll`。
- 用户运行时报系统错误。

正确处理：

- 修改 `.pro` 后必须重新部署运行库。
- 打包前必须运行 `deploy.ps1`。
- 测试包必须独立启动验证。

以后应避免：

- 不能只编译通过就认为可运行。
- Qt 程序新增模块后要重新跑 `windeployqt`。

### 11. 没有一开始就把所有文本框右键菜单中文化

问题：

- 部分文本框右键菜单仍是英文。
- 单纯加载 Qt 中文翻译文件不够。

正确处理：

- 增加全局事件过滤器。
- 对标准菜单项手动翻译。
- 保留快捷键后缀。

以后应避免：

- Qt 标准控件不一定完全本地化。
- 中文软件要检查右键菜单、弹窗按钮、系统菜单等细节。

### 12. 对用户“少使用英文”的要求执行不够彻底

问题：

- 早期界面中保留了 Dictate、Translate、Ask anything 等英文。
- 用户要求必须少用英文，必要时加括号。

正确处理：

- 主文案使用中文。
- 英文只作为括号解释或模型官方名。
- 模型名属于官方名，可以保留。

以后应避免：

- 不要默认用英文功能名。
- 用户明确要求中文时，导航、按钮、状态、提示都要中文。

### 13. 对“当前状态”区域的信息价值判断不准确

问题：

- 最初显示了很多不必要状态：
  - 自定义功能可新增。
  - 提示词锁定可设置。
  - 接口配置可填写。
  - 全局快捷键已注册。
  - 自动写入。

用户认为这些没有必要。

正确处理：

- 当前状态只显示运行时真正影响体验的状态。

以后应避免：

- 不要把“功能入口说明”放进状态面板。
- 状态面板应只显示当前运行状态。

### 14. 对“设置页滚动区域”的理解出现偏差

问题：

- 用户要求设置页可滚动，我一开始容易把较大区域都做成滚动。
- 用户实际想要的是必要的那一小部分能滚动，而不是整个页面都滚。

正确理解：

- 固定头部、标签页和底部按钮。
- 只让长内容区域滚动。

以后应避免：

- 滚动区域要精确，不要把整个窗口变成滚动页。

### 15. 没有一开始就按真实使用者视角审视 UI

问题：

- 部分设计开发者能理解，但新用户不一定能理解。
- 例如保存按钮在滚动底部、提示框持续置顶、状态面板信息过多。

正确方向：

- 新用户第一次打开就能看到关键操作。
- 危险或敏感行为要克制。
- 常用按钮要固定可见。
- 弹窗要提醒但不打扰。

## 四、下次用 AI 开发 Qt 软件时，应提前告诉 AI 的注意事项

建议直接复制下面这段给新的 AI：

```text
这个项目是 Windows Qt 5.9 桌面软件。请注意：

1. 界面必须以中文为主，英文只在模型官方名或必要说明中出现。
```

## 五、当前建议保留的验证流程

每次修改后建议执行：

```powershell
$env:QT_BIN="D:\Qt\5.9\mingw53_32\bin"
$env:MINGW_BIN="D:\Qt\Tools\mingw530_32\bin"
$env:OPENSSL_BIN="D:\Qt\Tools\mingw530_32\opt\bin"
$env:PATH="$env:MINGW_BIN;$env:QT_BIN;$env:PATH"
& "$env:QT_BIN\qmake.exe" vocekit.pro
& "$env:MINGW_BIN\mingw32-make.exe" -f Makefile.Debug -j2
& "$env:MINGW_BIN\mingw32-make.exe" release -j2
powershell -ExecutionPolicy Bypass -File .\scripts\deploy.ps1 -Configuration debug
powershell -ExecutionPolicy Bypass -File .\scripts\deploy.ps1 -Configuration release
powershell -ExecutionPolicy Bypass -File .\scripts\package-test.ps1
```

检查重点：

- 本地调试版能启动。
- 发布版能启动。
- 测试包能独立启动。
- 测试包不包含真实密钥。
- 测试包不包含录音、历史、源码和中间文件。
- 小窗口下文字不裁剪。
- 设置页按钮始终可见。
- 全局快捷键不会冲突。
- 安全软件不报高危行为。

## 六、2026-06-05 追加迭代

本次继续完善用户选择的高级体验：

- 结果小框增加“重新生成”“换模型重试”“继续追问”“展开全文”，并保留复制、写入、替换选中、关闭。
- 大模型结果支持流式显示，结果会边生成边进入小框，不再只能等待完整返回。
- 主页功能卡片支持拖动排序，排序保存到配置文件。
- 浮动条在录音时显示麦克风输入波形，用来判断是否真的收到声音。
- 常规设置增加录音前倒计时和录音提示音，用户可以自己决定是否开启。
- 测试诊断和常见问题继续补充，新增功能若出现报错或异常状态，应同步补充解决办法。
- 删除敏感服务状态相关检查。这个软件只应该验证接口是否能连通、鉴权和返回结果，不应该主动检查和当前软件功能无关的敏感信息。

后续继续开发时要注意：

- 流式输出需要兼容网络代理、TUN、透明代理和服务端断流，失败时必须给出可操作解释。
- 结果小框的高级按钮本质上会再次调用模型，要防止用户误以为只是本地操作。
- 波形只说明本机麦克风有输入，不等于云端识别一定成功。
- 所有新增弹窗报错都要同步进入“常见问题”，不能只在代码里处理。

# 2026-06-28 输出计划与运行上下文整理

## 本次调整

- `ResultOutputRouter` 从“只判断输出目标”扩展为“生成输出计划”。
- 输出计划现在包含：
  - 输出目标：自动写入、结果小框、截图面板。
  - 是否替换选中文字。
  - 写入前后的浮动条文案。
  - 运行日志动作名。
- `VoiceController::finishMode()` 不再自己拼写入文案和替换策略，而是读取 `ResultOutputPlan`。
- 旧的 `LastRunContext` 过渡类型已经删除，所有单次运行上下文统一使用 `VoiceRunContext`。

## 影响范围

- 用户功能不变：
  - 自动写入仍然按功能设置执行。
  - 有选中文字时仍然可以替换选区。
  - 截图输入仍然可以走截图结果面板。
  - 其他情况仍然走结果小框。
- 架构边界更清楚：
  - `VoiceController` 负责执行流程。
  - `ResultOutputRouter` 负责决定结果如何展示或写入。
  - `VoiceRunContext` 负责承载“输入收集 -> 识别 -> 模型处理 -> 输出”的上下文。

## 后续拆分建议

1. 把 `finishMode()` 中的历史保存、词库修正和输出执行继续拆成独立管线。
2. 让结果小框、截图面板和自动写入都通过同一个输出执行器调用。
3. 继续减少 `VoiceController` 对 UI 控件的直接依赖。

# 2026-06-28 功能执行规划拆分

## 本次调整

- 新增 `src/domain/voice_run_planner.h` 和 `src/domain/voice_run_planner.cpp`。
- `VoiceController::runContext()` 不再自己判断听写、翻译、问答和自定义功能该使用哪段输入文本。
- 新模块 `VoiceRunPlanner` 负责把 `VoiceRunContext` 转换成 `VoiceRunModelPlan`：
  - 当前功能类型。
  - 主输入文本。
  - 语音补充要求。
  - 问答问题。
  - 自定义功能语音要求。
  - 截图翻译的额外约束。
  - 是否含有语音输入。

## 为什么这样拆

- 以前 `VoiceController` 同时负责 UI 状态、录音、识别、模型请求、结果展示和输入规则判断。
- 这一步先把“输入规则判断”移到领域模块，后续可以继续把完整执行管线拆出来。
- `VoiceRunPlanner` 不依赖窗口、网络、设置保存或剪贴板，测试成本低，也不影响用户可见行为。

## 已覆盖的规则

- 翻译：有选中文字和语音时，选中文字作为主文本，语音作为补充要求。
- 问答：纯文本模式下不把旧语音内容当成问题。
- 自定义功能：语音输入会作为自定义功能的用户要求。
- 截图翻译：自动加入逐行翻译和保持文字块顺序的约束。

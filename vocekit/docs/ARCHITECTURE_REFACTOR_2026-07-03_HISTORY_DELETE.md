# 2026-07-03 历史删除逻辑拆分

## 本次改动

- 在 `HistoryStore` 中新增 `relatedFilesForEntry()`，集中计算一条历史记录关联的录音、文本和详情文件。
- 在 `HistoryStore` 中新增 `removeEntryFiles()`，集中处理关联文件去重和删除。
- 历史页里的 `deleteHistoryEntryFiles()` 改为薄包装，只调用存储层接口。
- 扩展 `history_store_tests`，覆盖关联文件去重和删除存在文件的行为。

## 为什么拆分

历史页后续要改成独立页面类。如果文件删除规则继续留在页面方法里，页面会同时负责 UI、筛选、文件结构和删除细节，迁移风险会变高。

拆分后：

- 文件结构知识集中在 `HistoryStore`。
- 页面只负责确认用户意图和刷新界面。
- 批量删除、单条删除和后续可能的历史清理工具可以复用同一套删除规则。

# 结果小框和生成流程设计

## 目标

本批次改善大模型生成和结果处理体验，同时保持现有配置可继续使用：

- 自动保存尚未完成或尚未处理的生成现场。
- 流式请求中断后自动切换普通请求重试一次。
- 每个功能独立决定结果小框按钮是否显示以及排列顺序。
- 支持调整结果小框透明度。
- 测试工具可以预览不同结果模板、透明度和按钮组合。
- 每个功能分别设置语音识别、图片识别和大模型请求的网络策略。

## 配置兼容原则

不整体替换现有 `settings.json` 结构，只增加字段。旧配置缺少新字段时使用兼容默认值，保存后自动写入新结构。

### 内置功能配置

新增三个顶层对象：

```json
{
  "resultActions": {
    "dictate": ["regenerate", "retryModel", "followUp", "expand", "vocabulary", "copy", "write", "replace"],
    "translate": ["regenerate", "retryModel", "followUp", "expand", "vocabulary", "copy", "write", "replace"],
    "ask": ["regenerate", "retryModel", "followUp", "expand", "vocabulary", "copy", "write", "replace"]
  },
  "networkPolicies": {
    "dictate": {
      "speech": "inherit",
      "ocr": "inherit",
      "model": "inherit"
    }
  },
  "resultPopupOpacity": 100
}
```

### 自定义功能配置

每个 `customFunctions` 项新增：

```json
{
  "resultActions": ["regenerate", "retryModel", "followUp", "expand", "vocabulary", "copy", "write", "replace"],
  "networkPolicy": {
    "speech": "inherit",
    "ocr": "inherit",
    "model": "inherit"
  }
}
```

### 默认值和清理规则

- 旧配置默认显示当前已有的全部操作按钮，视觉和行为不发生突变。
- `close` 不进入配置，始终显示在最后，保证窗口可以关闭。
- 未知操作标识在读取时忽略。
- 重复操作标识只保留第一次出现的位置。
- 网络策略只接受 `inherit`、`direct`、`systemProxy`。
- 图片使用本地 RapidOCR 或 Windows OCR 时，图片网络策略不产生网络请求。
- 透明度限制为 60% 至 100%，旧配置默认 100%。

## 功能页面

在每个听写、翻译、问答和自定义功能的“输出控制”中增加两个折叠项。

### 结果操作

- 展示可拖动排序的操作列表。
- 每行包含拖动手柄、操作名称和开关。
- 支持的操作为：重新生成、换模型、继续追问、展开全文、加入词库、复制、写入、替换选中。
- 修改开关或顺序后立即保存。
- 操作因当前上下文不可用时仍按配置保留，但按钮在结果窗口中禁用。例如没有选中文字时“替换选中”不可用。

### 网络策略

分别提供三个下拉框：

- 语音识别：跟随全局、始终直连、使用系统代理。
- 图片识别：跟随全局、始终直连、使用系统代理。
- 大模型：跟随全局、始终直连、使用系统代理。

修改后立即保存。单次功能执行开始时生成不可变的网络策略快照，执行中修改设置只影响下一次执行。

## 网络策略执行

`ApiClient` 不再只依赖一个全局代理状态。每次网络调用都接收本次请求使用的策略：

1. `inherit`：使用“设置 -> 网络”中的全局选择。
2. `direct`：对本次请求强制使用 `QNetworkProxy::NoProxy`。
3. `systemProxy`：对本次请求使用系统代理配置。

语音识别、云端图片识别和大模型请求分别使用功能配置中的对应策略。为避免并发请求互相覆盖代理设置，每次请求使用独立的 `QNetworkAccessManager` 或请求作用域管理器，不在共享管理器上临时切换后再恢复。

## 流式失败回退

结果小框仍优先使用流式请求。满足以下条件时自动执行一次普通请求：

- 流式连接超时、连接关闭、代理中断或未返回完整结果。
- 流式解析失败，且服务端没有返回明确业务错误。
- 流式返回了部分文本，但连接以网络错误结束。

以下错误不自动重试：

- 401、403 等认证或权限错误。
- 404 或明确的模型不存在错误。
- 429 限流。
- 请求参数错误。
- 用户取消。

回退流程：

1. 结果小框显示“流式连接中断，正在使用普通请求重试”。
2. 清除不完整流式文字，避免新旧内容拼接。
3. 使用同一模型、提示词、输入内容和网络策略发起一次普通请求。
4. 成功后显示完整结果并在日志中记录回退原因和两次耗时。
5. 失败后保留清楚错误信息，不再进行第二次重试。

## 自动保存现场

使用 `config/runtime/recovery.json` 保存一个当前现场，采用原子写入，不保存 API 密钥。

保存内容包括：

- 功能编号和功能名称。
- 输入类型、选中文字、语音识别文字、图片识别文字。
- 当前模型、提示词编号和网络策略快照。
- 已生成文字、用户编辑后的文字。
- 当前阶段：准备、识别、流式生成、普通请求回退、结果待处理。
- 创建时间和最后更新时间。

保存时机：

- 开始识别或模型生成时创建。
- 每收到一批流式文字后采用短延迟合并保存，避免频繁写盘。
- 结果小框中的文字被用户修改后延迟保存。
- 进入普通请求回退时立即更新阶段。

清理时机：

- 用户执行复制、写入、替换选中或明确关闭结果小框后清理。
- 任务正常失败并已写入历史记录后清理。
- 用户在恢复提示中选择丢弃后清理。

程序启动时发现恢复文件：

- 显示一次“发现未完成内容”提示。
- 可选择恢复到结果小框、查看内容或丢弃。
- 恢复只展示已保存内容，不自动重新调用接口。

## 结果小框

- 使用全局 `resultPopupOpacity` 设置窗口透明度。
- 用户修改透明度后立即生效并保存。
- 根据当前功能的 `resultActions` 创建按钮并按配置顺序排列。
- 高级操作和结果操作仍可分成两行，但同一行内严格遵循用户排序。
- 关闭按钮固定在末尾。
- 复制、写入和替换选中执行成功后视为现场已处理。
- 普通关闭视为用户明确关闭，同时保留现有“修改后保存草稿到历史”的行为。

## 测试工具

“结果小框测试”改为先显示测试设置：

- 结果模板：简洁、详细、对照原文、仅输出结果。
- 透明度：60% 至 100%。
- 功能来源：听写、翻译、问答或任一自定义功能。
- 操作按钮：读取所选功能配置，也可在测试中临时勾选预览。
- 状态：生成中、流式失败回退中、完成。

测试仅预览界面，不调用真实模型，不修改功能配置；只有明确点击“应用到该功能”时才保存按钮组合。

## 错误处理和日志

新增日志事件：

- 现场创建、更新、恢复、清理失败。
- 流式失败原因、已接收字数、是否触发回退。
- 普通请求回退开始、完成或失败。
- 本次使用的语音、图片和模型网络策略。

所有新增弹窗错误继续使用现有问题编号体系，并在常见问题中加入：

- 恢复文件损坏或无法写入。
- 流式失败且普通请求也失败。
- 指定系统代理但系统未配置可用代理。
- 直连被 TUN 或透明代理接管。

## 测试范围

- 配置读取、默认值、非法值清理和保存回读。
- 旧配置迁移后行为不变。
- 结果操作排序、隐藏、固定关闭按钮和不可用状态。
- 三类请求分别选择不同网络策略。
- 流式网络失败触发一次普通请求。
- 鉴权、限流、模型不存在和用户取消不触发回退。
- 恢复文件的原子保存、恢复和清理。
- 结果小框透明度边界。
- 测试工具模板和按钮组合预览。
- 现有截图、录音、文字识别、历史记录和 SSL 回归测试。

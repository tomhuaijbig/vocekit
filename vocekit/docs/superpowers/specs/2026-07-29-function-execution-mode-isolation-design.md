# 普通模式与画布模式隔离设计

## 背景

当前每个功能同时拥有普通设置和功能画布：

- 普通设置保存在 `FunctionSettings` 的输入、录音、模型、提示词和输出字段中。
- 画布设置保存在 `FunctionFlowState` 的草稿、发布版本和编辑器状态中。

两套配置虽然已经分别保存，但仍共用 `flow.enabled` 参与运行分流。画布未启用、缺少当前入口或发布数据不可用时，运行路径可能回退普通流程。这会让用户难以判断快捷键实际执行哪套配置，也不符合“两套配置互不代替”的预期。

## 目标

1. 每个功能明确选择“普通模式”或“画布模式”。
2. 普通配置和画布配置分别保存，互不复制、互不覆盖。
3. 运行时只执行当前选择的模式，不跨模式回退。
4. 编辑画布与选择运行模式是两个独立动作。
5. 兼容现有设置文件，并保持现有用户的有效模式。
6. 模式切换失败时保留原模式，不留下半完成状态。

## 非目标

- 不把一个功能复制成两个侧边栏项目。
- 不复制功能名称、排序和主快捷键。
- 不删除普通配置、画布草稿或历史发布版本。
- 不改变画布的 DAG、草稿、发布、撤销和运行中冻结语义。
- 不改变普通模式内部的录音、截图、模型和结果展示实现。

## 配置模型

### 唯一运行模式

新增类型：

```cpp
enum class FunctionExecutionMode
{
    Classic,
    Canvas
};
```

`FunctionSettings` 增加 `executionMode`，默认值为 `Classic`。JSON 使用稳定字符串：

- `classic`
- `canvas`

`executionMode` 是运行分流的唯一事实来源。普通设置与画布设置仍保留在现有字段中：

```text
FunctionSettings
├── identity
│   ├── id
│   ├── name
│   ├── shortcut
│   └── order
├── classic configuration
│   ├── input
│   ├── recording
│   ├── modelId / promptId / prompt
│   ├── output
│   └── network
├── executionMode
└── canvas configuration
    └── flow
        ├── draft
        ├── published
        └── editor
```

功能身份继续共用，因为方案仍是“同一个功能选择一种执行方式”。普通配置与画布配置不共用运行参数。

### `flow.enabled` 兼容规则

`flow.enabled` 不再作为运行判断条件，也不再作为独立可编辑状态。它只作为旧版本兼容镜像：

- 写出设置时，`executionMode == Canvas` 对应 `flow.enabled = true`。
- 写出设置时，`executionMode == Classic` 对应 `flow.enabled = false`。
- 内存中的模式判断只读取 `executionMode`。
- 任何保存路径都通过统一规范化函数同步兼容镜像，禁止调用方分别修改两个状态。

这样可以避免 `executionMode` 与 `flow.enabled` 互相矛盾，同时让旧版本仍能按照原字段读取大致相同的启用状态。

## 迁移与兼容

读取旧设置时：

1. 如果存在合法的 `executionMode`，它优先。
2. 如果不存在 `executionMode`：
   - `flow.enabled == true` 迁移为 `Canvas`。
   - 其他情况迁移为 `Classic`。
3. 未知的 `executionMode` 值保留在 retained 数据中，当前版本按 `Classic` 安全运行。
4. 规范化后同步 `flow.enabled` 兼容镜像。

迁移不会自动发布草稿，也不会把“只有草稿”视为可运行的画布模式。旧配置已经处于 `flow.enabled == true` 时，仍保留画布模式；若其发布数据损坏，运行时报告配置错误而不回退普通流程。

## 界面设计

### 模式选择

功能页标题区域增加清晰的双选控件：

```text
当前执行  [普通模式] [画布模式]
```

要求：

- 两个选项互斥。
- 当前生效模式始终可见。
- 设置页和画布页显示相同状态。
- 模式切换不自动导航页面。
- 模式保存成功后才更新选中状态。
- 保存或校验失败时恢复原选项，并显示明确原因。

### 页面导航

现有“画布”按钮改为“编辑画布”。它只负责进入画布编辑页：

- 在普通设置页显示“编辑画布”。
- 在画布页显示“返回设置”。
- 进入或退出画布不改变 `executionMode`。
- 返回设置前仍按现有规则刷新并保存待处理画布草稿和视口状态。

### 发布动作

画布底部的“应用流程”改为“发布流程”：

- 发布只更新 `flow.published`。
- 发布不会自动把 `executionMode` 改为 `Canvas`。
- 普通模式下发布成功，提示“流程已发布；切换到画布模式后生效”。
- 画布模式下发布成功，新发布版本在运行时缓存刷新后生效。

原“停用流程”按钮移除。切换到普通模式就是停止使用画布运行的唯一入口，画布草稿和发布版本继续保留。

## 模式切换

### 普通模式切换到画布模式

切换必须通过领域服务完成，不允许 UI 直接改字段。服务按顺序执行：

1. 读取当前功能及其最新设置快照。
2. 确认存在受支持且修订号大于零的发布版本。
3. 复核发布图哈希。
4. 使用发布图自身引用的模型、提示词及当前运行环境验证发布图；不得读取普通模式的模型、提示词字段作为画布运行参数。
5. 编译发布图。
6. 原子保存 `executionMode = Canvas` 及兼容镜像。
7. 发布设置变更事件，刷新运行计划、快捷键和界面状态。

任一步失败时：

- 保持 `Classic`。
- 不修改发布版本和草稿。
- 不刷新成画布运行状态。
- 向用户显示具体错误。

### 画布模式切换到普通模式

切换到普通模式始终允许：

1. 原子保存 `executionMode = Classic` 及兼容镜像。
2. 从运行计划缓存中移除该功能的画布计划。
3. 刷新普通模式快捷键和启动入口。
4. 保留画布草稿、发布版本和视口状态。

模式切换本身不离开当前页面，也不删除正在编辑但尚未发布的画布内容。

### 并发与失败

- 使用最新设置快照合并模式字段，不能用旧快照覆盖普通设置或画布数据。
- 模式保存与草稿保存使用各自稳定的设置变更键。
- 远端或另一窗口更新模式时，当前页面刷新模式控件，但不覆盖本地未保存草稿。
- 模式保存失败时不发送运行时刷新事件。
- 正在运行的流程继续使用启动时冻结的计划；新模式只影响下一次启动。

## 运行时分流

### 普通模式

`executionMode == Classic` 时：

- 不查询画布计划。
- 不启动画布执行控制器。
- 完全使用现有普通流程。
- 画布草稿和发布版本不影响本次运行。

### 画布模式

`executionMode == Canvas` 时：

- 只使用已验证、已编译的发布计划。
- 不读取普通配置作为运行参数。
- 不调用普通流程作为兜底。

如果发布计划损坏、缓存缺失、模型或提示词失效，返回配置错误并终止本次启动。

如果当前触发入口未在发布计划中配置：

- 返回稳定错误码 `flow_trigger_not_configured`。
- 显示“当前画布未配置此入口”。
- 不运行普通流程。
- 不产生第二份历史记录或输出。

普通模式与画布模式仍共用跨模式忙碌互斥，防止两个模式并发处理同一功能。已经开始的运行不会因为用户切换模式而中途换用另一套配置。

## 快捷键与入口

- 功能主快捷键属于功能身份，因此两种模式共用它的键值。
- 普通模式下，主快捷键和辅助入口按普通配置注册。
- 画布模式下，主快捷键和画布发布计划定义的入口只路由到画布启动器。
- 画布模式不得把未匹配入口转交普通启动器。
- 只有实际存在键值的入口可以被系统注册；没有快捷键的入口通过页面、托盘或其他启动器触发时仍遵守“不回退”规则。

## 设置事件

新增独立设置变更键，例如：

```text
function.executionMode
```

该事件需要刷新：

- `FunctionFlowPlanCache`
- 全局快捷键快照
- 功能页模式控件
- 首页和侧边栏中需要显示的当前模式状态

画布草稿和视口事件继续不刷新运行计划。画布发布事件只在当前模式为 `Canvas` 时替换运行计划；普通模式下保留发布数据但不提供运行计划。

## 错误处理

用户可见错误必须区分：

- 没有已发布流程。
- 发布流程版本不受支持。
- 发布图哈希不一致。
- 发布图验证或编译失败。
- 模型或提示词引用失效。
- 当前画布未配置此入口。
- 模式保存失败或发生版本冲突。

错误不得静默切换模式，也不得跨模式回退。模式控件必须反映持久化成功后的真实状态。

## 测试策略

### 配置和迁移

- 新字段 JSON 往返。
- 缺少新字段时按旧 `flow.enabled` 迁移。
- 新旧字段冲突时以 `executionMode` 为准。
- 未知值安全回到普通模式并保留原值。
- 普通设置保存不覆盖模式和画布。
- 画布保存不覆盖模式和普通设置。

### 模式服务

- 有效发布流程允许切到画布。
- 没有发布流程、哈希损坏、验证失败或编译失败时阻止切换。
- 切换失败不改变任何配置。
- 切回普通模式保留草稿和发布版本。
- 模式变更事件只在保存成功后发送。

### 运行时

- 普通模式只调用普通流程。
- 画布模式只调用画布流程。
- 画布模式缺少入口时返回 `flow_trigger_not_configured` 且普通调用次数为零。
- 画布配置错误时普通调用次数为零。
- 模式切换不改变已经运行中的冻结计划。
- 快捷键和 Launcher 使用同一严格分流规则。

### 界面

- 模式控件在设置页和画布页一致。
- “编辑画布”和“返回设置”只导航，不改变模式。
- “发布流程”不自动切换模式。
- 切换画布失败时控件恢复普通模式。
- 紧凑窗口、最大化和 150% 缩放下按钮文字不裁切。

## 验收标准

1. 用户能明确看到每个功能当前执行普通模式还是画布模式。
2. 编辑或发布画布不会自动改变执行模式。
3. 普通模式永远不运行画布。
4. 画布模式永远不运行普通流程。
5. 无有效发布流程时无法切到画布模式。
6. 画布缺少当前入口时显示明确错误且不回退。
7. 两套配置分别编辑和保存，互不覆盖。
8. 旧配置按原 `flow.enabled` 状态平滑迁移。
9. 切回普通模式不会删除任何画布数据。
10. 所有新增配置、服务、运行时、快捷键和界面测试通过。

# vocekit 讯飞与百度流式语音识别设计

## 目标

让讯飞语音听写和百度语音识别在录音过程中持续返回文字，并在现有悬浮条中像 AI 流式回答一样逐步显示。临时文字可以被服务商修正；停止录音并取得最终文本后，才执行一次现有 AI、翻译、问答或自动写入流程。

该功能同时覆盖普通录音和长录音。流式连接失败时，系统继续保存完整录音，并在停止后使用现有整段识别接口自动兜底。

## 当前情况

- 讯飞 Provider 已使用 WebSocket，但只在录音停止后把完整 PCM 按帧发送，界面无法在录音过程中取得结果。
- 百度 Provider 使用一次性 REST 请求，只能在停止录音后上传完整音频。
- `SpeechProvider` 只提供同步的整段 `recognize(...)` 结果，没有临时结果回调。
- 录音器只把 PCM 写入文件并计算音量峰值，没有把实时 PCM 提供给识别会话。
- 当前 WebSocket 传输抽象接收预先准备好的文本帧，不支持录音期间持续推送二进制帧或逐条接收结果。

## 已确认的产品规则

- “实时识别”默认开启，并在语音设置中提供关闭开关。
- 实时文字显示在现有悬浮条中；悬浮条录音时向下展开，不增加另一套字幕窗口。
- 录音过程中只做语音识别和文字预览，不提前运行 AI，也不把临时文字写入当前应用。
- 停止录音并取得最终文本后，现有后续流程只执行一次。
- 普通录音和长录音都使用流式识别。
- 讯飞会话在到达官方单会话时限前自动续接。
- 百度缺少实时识别所需配置、实时接口不可用或未授权时，自动使用现有整段 REST 识别。
- 流式识别中途失败时保留预览，停止后用完整录音重新识别，成功结果替换全部预览。
- 点击“取消”或按 Esc 时放弃本次录音，不执行整段兜底，也不运行后续流程。

## 非目标

- 不在本次工作中让 AI 对每个已确认句子提前运行。
- 不允许用户在录音过程中编辑临时文字。
- 不新增独立字幕气泡、主窗口字幕页或 A/B 显示位置切换。
- 不为讯飞、百度以外的语音服务商实现流式协议。
- 不增加逐字时间戳、说话人分离或会议角色识别。
- 不用周期性重复上传整段录音模拟流式效果。

## 总体架构

采用统一的流式语音会话边界，而不是让录音器、控制器和两个 Provider 彼此直接依赖。

录音期间的数据流为：

1. 录音设备产生 16 kHz、单声道、16-bit PCM。
2. 录音器继续把完整 PCM 写入现有文件，同时把 PCM 副本交给当前流式会话。
3. 流式会话按服务商要求组帧并发送。
4. 服务商返回临时或最终片段。
5. 统一文字归并器生成“已确认文字 + 临时文字”的完整快照。
6. 控制器把快照传给悬浮条，只更新预览。
7. 停止录音后，控制器等待最终文本；成功时把最终文本交给现有工作流一次。

如果流式会话不可用或运行中失败，完整录音仍然存在。停止后控制器调用现有 `SpeechProvider::recognize(...)`，取得最终文本后再进入原有流程。

## 模块边界

### 实时 PCM 出口

录音层新增一个只读 PCM 数据出口。它只负责发布已经采集的字节和音频格式，不认识讯飞、百度、文字结果或界面。

- 写入完整录音文件仍是主路径，不能因网络速度降低或失败而中断。
- 音频回调不得执行网络 I/O，不得阻塞采集线程。
- PCM 数据通过有界队列交给网络会话。队列最多缓存约 2 秒音频；超过上限说明实时链路无法跟上，当前流式会话转为失败状态，录音继续，停止后走整段兜底。
- 录音器原有音量峰值、文件格式和停止行为保持不变。

### 统一流式会话

新增流式会话接口，职责限定为：

- `start`：校验配置并建立服务商会话。
- `pushAudio`：接收 PCM，不阻塞调用方。
- `finish`：发送结束信号并等待最终结果。
- `cancel`：立即结束网络会话并忽略后续消息。

会话通过回调或 Qt queued signal 发布状态和文字更新。外部接收的是统一快照，不需要理解讯飞 `pgs/rg` 或百度 `MID_TEXT/FIN_TEXT`。

保留现有同步 `SpeechProvider::recognize(...)`。它继续服务于文件识别、关闭实时识别的情况和失败兜底，避免破坏现有调用者。

### 文字归并器

文字归并器是与网络和 UI 无关的纯逻辑单元，保存：

- 已确认片段；
- 当前临时片段；
- 服务商片段序号及必要的替换范围；
- 当前完整预览文本。

每次输入服务商事件后，它输出完整快照，而不是要求 UI 自己拼增量。这样可以集中处理替换、乱序保护和会话续接，也能用纯单元测试覆盖。

### 工作流控制器

现有语音录音工作流控制器负责一次录音的生命周期：

- 依据开关、服务商和凭据决定流式或普通模式；
- 创建会话并连接 PCM 出口；
- 把文字快照传给悬浮条；
- 处理停止、取消、超时和失败兜底；
- 只把最终文本交给后续执行管线一次。

每次录音生成独立执行编号。来自旧编号、已取消会话或已结束会话的迟到回调全部忽略，防止污染下一次录音。

## 讯飞协议适配

- 继续使用现有鉴权 URL 和 WebSocket 连接逻辑。
- 第一帧业务参数开启 `dwa=wpgs`，允许动态修正。
- PCM 按官方建议聚合为 1280 字节、约 40 毫秒一帧，使用状态 0、1、2 表示首帧、中间帧和结束帧。
- 解析结果中的 `sn`、`pgs` 和 `rg`。`apd` 追加片段；`rpl` 按 `rg` 指定范围替换旧片段。
- 单会话录音到约 55 秒时主动结束并建立下一会话，避开 60 秒限制。切换期间的新 PCM 暂存在有界队列，新连接建立后按顺序发送。
- 上一会话的已确认文本作为固定前缀保留；下一会话只能修改自己的片段，不能修改已经封存的上一会话内容。
- 续接建立失败时停止流式链路，但继续完整录音，最终走整段兜底。

## 百度协议适配

- 实时模式连接官方实时语音识别 WebSocket。
- 首帧发送 START 文本消息，包含 AppID、API Key、设备标识、模型、PCM 格式和 16000 采样率。
- 音频使用二进制帧，聚合为官方推荐的约 160 毫秒、5120 字节一帧。
- `MID_TEXT` 更新当前临时文字；`FIN_TEXT` 把本段文字转为已确认内容并清空临时部分。
- 正常停止发送 FINISH；用户取消发送 CANCEL，并忽略之后的消息。
- 百度实时模式要求 AppID 和 API Key。缺少任一项时不建立实时连接，直接使用普通录音模式；停止后由现有 API Key + Secret Key 的 REST 路径识别。
- 实时服务返回鉴权、权限或协议错误时，本次录音标记为需要整段兜底，不在录音期间反复重连或反复鉴权。

## 设置与配置

在语音设置中增加“实时识别”开关，持久化为布尔配置，默认值为开启。旧配置没有该字段时按开启处理。

服务商详情需要明确显示当前模式是否具备实时识别条件：

- 讯飞：沿用现有语音听写所需凭据校验。
- 百度：AppID 和 API Key 可启用实时模式；API Key 和 Secret Key 可启用整段 REST 兜底。

百度 AppID 不再笼统标记为“可选”，而是说明“实时识别必填；仅使用整段识别时可留空”。保存设置时允许留空，因为留空会产生明确的降级行为，不应阻止用户继续使用原有 REST 功能。

关闭实时识别后，两个服务商均完全使用现有停止后整段识别流程，悬浮条不展开实时文字区。

## 悬浮条界面

- 保持现有悬浮条宽度和主要按钮位置。
- 录音开始后向下展开文字区；文字区最多显示三行，内容增长时自动跟随最新一行，悬浮条不无限增高。
- 已确认文字使用正常前景色；仍可能被修正的临时文字使用蓝色，并显示轻量输入光标。
- 临时文字只读，不获取键盘焦点，不影响停止和取消快捷操作。
- 点击停止后显示“正在定稿…”，保留当前预览，等待最终结果。
- 流式失败后显示“流式连接已中断，停止后将重新识别”；用户停止时改为“正在重新识别…”。
- 最终结果返回后替换全部临时预览，再沿用现有成功状态、结果展示和收起行为。
- 用户取消时立即清空文字区并恢复现有取消状态。

## 状态机与时序

一次录音只允许沿以下路径之一结束：

### 流式成功

`RecordingStreaming -> FinalizingStreaming -> Completed`

停止后最多等待最终流式结果 5 秒。只有取得去除首尾空白后仍非空的最终文本才进入 `Completed`，并只触发一次后续流程；空最终文本视为流式结果不完整，进入整段兜底。超时后到达的流式消息由状态和执行编号门禁忽略。

### 流式失败后兜底

`RecordingStreaming -> StreamingDegraded -> RecognizingFallback -> Completed/Failed`

失败后不再把新的流式结果视为有效，但继续录音。停止后使用完整录音执行一次现有整段识别。兜底取得非空结果时替换全部预览；请求失败或结果为空时进入 `Failed`，显示现有可诊断错误，不执行 AI 或自动写入。

### 开始时不可流式

`RecordingBatchOnly -> RecognizingFallback -> Completed/Failed`

实时开关关闭、服务商不支持或凭据不足时，从录音开始就使用普通模式。录音期间不显示伪造的流式结果，停止后执行现有整段识别。

### 取消

任意录音或定稿状态收到取消后进入 `Cancelled`。控制器停止采集并取消网络会话，丢弃预览，不执行整段兜底，也不调用后续流程。

## 线程、资源与退出

- 音频采集线程只复制 PCM 到有界队列。
- WebSocket 建连、发送、接收和协议解析在网络会话所属线程执行。
- 悬浮条和控制器状态变化通过 queued signal 回到 Qt 主线程。
- `finish`、`cancel`、窗口退出和应用退出都必须释放 WebSocket、计时器及排队音频。
- 回调以执行编号和会话存活状态为双重门禁；QObject 生命周期使用父子所有权或安全的弱引用，不捕获已经销毁的界面对象。

## 错误处理与日志

错误至少区分配置错误、鉴权或权限错误、网络错误、协议错误、发送队列溢出、最终结果超时和用户取消。

- 配置错误在开始时本地判断，不发送必然失败的请求。
- 网络、协议、队列溢出和 5 秒定稿超时均进入整段兜底。
- 取消不是失败，不显示错误通知。
- 日志可以记录服务商、执行编号、状态转换、错误类别和服务端错误码。
- 日志不得记录 API 密钥、签名后的鉴权 URL、完整音频或完整识别文本。

## 后续流程隔离

临时文字和分段最终文字都不能直接进入现有功能执行管线、历史记录或系统写入。

只有控制器确认本次录音得到唯一最终文本后，才调用一次现有后续流程。无论发生讯飞续接、百度多个 `FIN_TEXT`、超时或整段兜底，执行管线看到的仍是一份最终文本和一次调用，功能草稿、AI 提示词、翻译、问答及自动写入规则均不改变。

## 测试策略

所有自动化协议测试使用模拟 WebSocket、假时钟和假整段识别器，不连接真实讯飞或百度接口，不依赖真实密钥，不消耗额度。

### 纯逻辑测试

- 讯飞 `apd` 追加、`rpl` 替换、`rg` 范围、重复和乱序消息。
- 百度多个 `MID_TEXT`、`FIN_TEXT` 以及临时文字转已确认文字。
- 会话续接后旧片段封存，新片段只能追加或修改本会话范围。
- 最终快照不重复、不丢失，空结果行为明确。

### 协议测试

- 讯飞鉴权、首中尾帧、40 毫秒节奏、动态修正参数和约 55 秒续接。
- 百度 START 字段、二进制音频帧、FINISH、CANCEL、160 毫秒聚合和结果类型解析。
- 配置错误不创建传输；鉴权、断网、协议错误和队列溢出只上报一次失败。

### 录音与控制器测试

- PCM 同时写入完整文件和流式出口，保存的音频字节与原行为一致。
- 网络发送变慢时不阻塞音频采集或 Qt 主线程。
- 流式成功不调用整段识别；流式失败只调用一次整段识别。
- 停止后 5 秒超时进入兜底。
- 取消不兜底、不运行后续流程。
- 迟到回调及上一执行编号的回调被忽略。
- 长录音跨讯飞会话仍只产生一次最终工作流调用。

### 界面与可用性测试

- 实际悬浮条覆盖录音、文字修正、定稿、失败兜底、成功和取消状态。
- 三行长中文、连续英文、空格和标点不会裁切按钮或让悬浮条无限增高。
- 在 100%、125%、150% 缩放和放大字体下检查文字、状态和按钮。
- 确认临时文字只读、不抢焦点，停止和取消始终可操作。
- 使用真实 widget 截图检查展开与收起状态，而不只依赖源码字符串断言。

### 回归与交付验证

- Qt 5.9、MinGW、C++11 Release 构建通过。
- 现有语音 Provider、录音工作流、悬浮条、设置和功能执行测试全部通过。
- 可运行交付目录包含 Qt 运行库和所需插件；在不依赖开发机 PATH 的环境中启动验证，不能只交付一个缺少 `Qt5Core.dll` 的 `vocekit.exe`。

## 性能目标

- 应用收到服务商文字消息后，归并并提交主线程显示的内部新增延迟不超过 100 毫秒。
- 网络和服务商正常时，首段临时文字目标约 1.5 秒内出现；这是体验目标，不把外部网络时延当作本地单元测试的硬失败条件。
- 音频采集、PCM 文件写入、界面动画和停止按钮不能被网络 I/O 阻塞。
- 文字更新采用“保留最新快照”的合并刷新，连续更新时最多每 50 毫秒刷新一次界面；不能因合并而回退到旧快照。

## 兼容与发布

- 新开关对旧配置默认开启，但只有讯飞和百度进入流式路径；其他服务商保持原行为。
- 现有 `SpeechProvider::recognize(...)` 接口和整段识别测试继续保留。
- 百度已有 AppID 为空的用户不需要立即修改配置，仍可使用原有 REST 识别。
- 如果新流式路径出现运行时问题，关闭“实时识别”即可恢复原有稳定流程，不需要迁移或删除凭据。

## 验收标准

- 选择讯飞或百度并启用实时识别后，录音期间悬浮条能持续显示临时文字。
- 服务商修正内容时，界面原位替换，不重复追加旧文字。
- 讯飞录音超过单会话限制后仍连续识别，最终文本顺序正确。
- 停止录音后只运行一次 AI、翻译、问答或自动写入。
- 百度缺少 AppID、流式断网或最终结果超时时，完整录音兜底成功且只执行一次后续流程。
- 取消录音不产生最终文本、不兜底、不写入、不运行 AI。
- 所有自动化测试无真实网络和密钥依赖；Release 构建、界面缩放检查和可运行目录启动检查全部通过。

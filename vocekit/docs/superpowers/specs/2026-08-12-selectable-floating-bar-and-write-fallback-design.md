# vocekit 可选漂浮窗与写入失败兜底设计

## 目标

在不改变现有语音识别、AI 处理和输出管线职责的前提下，提供两套用户可选的漂浮窗样式：简洁的“状态胶囊”和可查看流式文字的“实时文字卡片”。

自动写入继续优先把最终结果写入原目标窗口；当没有冻结的外部目标窗口、目标窗口失效或无法激活，或剪贴板与系统输入注入返回失败时，根据“写入失败兜底”设置自动弹出结果小框，避免文字丢失或误写到其它窗口。

## 已确认的产品规则

- 仅保留 B“状态胶囊”和 C“实时文字卡片”两套新样式，二者都以可点击卡片形式出现在设置页。
- B 是全局默认样式。
- 全局设置决定默认样式；每个自定义功能可选择“跟随全局”、B 或 C。
- “写入失败弹出结果小框”属于写入设置，不属于漂浮窗样式。
- 写入兜底默认开启。
- 用户主动取消任务时不触发写入兜底。
- 旧配置自动采用 B，并默认开启写入兜底。

## 非目标

- 不在本次工作中增加第三套漂浮窗样式。
- 不把实时临时文字持续写入目标窗口。
- 不改变语音服务商协议、模型请求协议或快捷键含义。
- 不重做现有结果小框；兜底直接复用其复制、写入、替换选中和关闭能力。
- 不把漂浮窗样式与“自动写入、结果小框、截图结果窗”等输出方式绑定。

## 方案选择

曾比较三种视觉方向：极简胶囊、状态胶囊和实时文字卡片。最终同时保留后两种：

- B 适合作为默认样式。它比纯图标方案多一层中文状态提示，新用户能判断软件正在录音、转录、AI 处理还是写入，同时保持较小占用。
- C 适合重度听写。它让用户看到已确认文字和仍可能修正的临时文字，但体积更大，因此作为主动选择而非默认。

两种样式共用同一个漂浮窗状态模型和动作回调，只替换渲染方式，避免维护两套任务状态机。

## 漂浮窗样式

### B：状态胶囊

录音阶段显示黑色圆角胶囊：

- 左侧叉号：取消本次任务；
- 中间动态波形：反馈麦克风输入；
- 右侧对号：立即结束录音并进入后续处理。

进入转录、AI 处理或写入阶段后，胶囊收缩为单行状态，例如“正在转录”“AI 处理中”“正在写入”。成功后短暂显示“已写入”或“处理完成”，再按现有显示时间收起。失败时显示简短失败状态，详细可操作结果由结果小框或现有错误界面承载。

### C：实时文字卡片

录音阶段显示紧凑黑色文字卡片：

- 顶部显示当前状态和可选录音时长；
- 正常前景色表示已确认文字；
- 蓝色表示服务商仍可能修正的临时文字；
- 卡片保留取消和完成录音动作；
- 内容只读，不获取输入焦点，不抢占目标应用的光标。

文字区采用有限高度，优先展示最新内容，不随长录音无限增长。进入定稿、AI 处理和写入阶段后，卡片可收缩为状态提示；任务完成后按现有显示时间收起。

当实时识别关闭、当前服务商不支持流式文字、实时连接降级或尚未收到文字时，C 显示准确的阶段状态，不制造伪流式文字。最终流程仍使用唯一的最终文本。

## 统一状态与动作

漂浮窗从控制器接收与外观无关的视图状态，包括：

- 阶段：准备、录音、转录定稿、AI 处理、写入、完成、失败和流式降级；
- 已确认文字和临时文字；
- 波形峰值；
- 当前动作是否可用；
- 自动收起时间。

两种样式映射相同动作：

- 叉号和对号只在录音准备/录音阶段可用；进入转录定稿、AI 处理或写入阶段后隐藏，不能让用户误以为仍可取消已经交给后续管线的任务；
- 点击叉号取消本次语音采集：经典流程不再启动识别/AI/写入；画布语音节点以 `Cancelled` 完成，并由现有画布执行器取消该次运行的剩余节点。不弹写入兜底结果框；
- 点击对号等同于正常结束录音并开始处理；
- 按住快捷键模式下，松开快捷键等同于点击对号；
- 用户拖动后继续复用现有位置保存与屏幕边界约束。

样式切换只影响下一次展示，不中途替换正在执行任务的窗口结构，避免控件重建造成回调丢失。

## 设置与继承

### 全局漂浮窗设置

全局设置页的“漂浮窗”区域提供 B 和 C 两张真实可点击预览卡片。选中状态必须清楚可见，并提供测试预览入口。全局默认值为 B。

持久化使用稳定标识，不保存界面文字：

- `statusPill`：B 状态胶囊；
- `liveTranscriptCard`：C 实时文字卡片。

### 自定义功能覆盖

每个自定义功能的展现设置增加漂浮窗样式选择：

- `inherit`：跟随全局，默认；
- `statusPill`：固定使用 B；
- `liveTranscriptCard`：固定使用 C。

解析时先读取功能覆盖；值为 `inherit`、为空或无效时使用全局值；全局值为空或无效时回退 B。功能卡片摘要应显示“漂浮窗：跟随全局 / 状态胶囊 / 实时文字卡片”，但不改变该功能原有输出方式。

## 写入失败兜底

### 设置位置与默认值

在“写入设置”中增加独立开关“写入失败时弹出结果小框”，默认开启。说明文字明确：该开关只在选择自动写入、且本地能够确认目标窗口或输入注入失败时生效。

经典功能的自动写入遵循此全局开关。画布中的“自动写入”节点继续保留节点级“失败时转结果小框”设置；节点级设置是该画布动作的明确配置，不被全局开关静默覆盖。

### 触发条件

开启兜底时，以下情况不尝试误写或在失败后立即弹出结果小框：

- 启动任务时保存的原目标窗口已经关闭或失效；
- 原目标窗口无法安全激活；
- 当前流程没有冻结的外部目标窗口；
- 系统输入注入或粘贴实际失败；
- 剪贴板暂时不可用。

兜底结果小框展示完整最终文字，并复用现有复制、再次写入、替换选中和关闭动作。错误提示说明未自动写入的原因，但不丢弃结果。

### 不触发条件

以下情况不属于写入失败，不触发该兜底：

- 用户点击叉号、按 Esc 或通过其它入口主动取消；
- 录音失败或没有取得语音文本；
- 语音识别失败；
- AI、翻译或问答处理失败；
- 自动写入成功。

如果当前画布流程已经显式连接结果小框，或自动写入节点的失败出口已由显式结果小框覆盖，不再重复创建第二个兜底窗口。

Windows `SendInput` 返回成功只能证明系统接受了粘贴按键，不能证明任意第三方应用内部的当前控件一定接收了文字。软件不得把剪贴板读回、固定延时或窗口仍在前台误称为“已验证写入”。因此，第三方应用静默拒绝粘贴但系统调用均成功的情况无法自动判定；用户仍可从历史记录取得结果，或主动选择“结果小框”输出方式。

## 输出数据流

正常自动写入：

1. 录音取得唯一最终文本。
2. 可选 AI 流程产生唯一最终输出。
3. 输出路由选择自动写入。
4. 写入器校验原目标窗口与输入条件。
5. 写入成功，漂浮窗显示完成状态后收起。

兜底路径：

1. 前三步与正常路径相同。
2. 写入前发现没有有效的冻结目标，或写入器返回可确认的激活、剪贴板或输入注入失败。
3. 输出控制器保留完整最终输出和原失败原因。
4. 若兜底开启且没有显式结果框覆盖，则创建一个结果小框。
5. 漂浮窗收起，用户在结果小框中决定复制、再次写入、替换或关闭。

临时流式文字只进入漂浮窗视图，不进入写入器、结果历史或后续 AI 管线。只有最终文本能够进入输出路由。

## 兼容与迁移

- 配置文件缺少漂浮窗样式时按 `statusPill` 处理。
- 自定义功能缺少覆盖字段时按 `inherit` 处理。
- 写入兜底字段缺失时按开启处理。
- 无效或未来版本未知样式不写坏原配置；运行时安全回退 B。
- 现有浮动条开关、位置、显示时间和流式识别开关继续有效。
- 现有自动写入、结果小框、截图结果窗三种输出方式的选择不变。
- 画布草稿中的自动写入节点配置不因读取全局设置被静默改写。

## 错误与生命周期

- 取消是正常终态，不显示“写入失败”。
- 迟到的识别、AI 或写入回调必须通过现有执行编号门禁，不得重新显示已取消的漂浮窗或兜底框。
- 一个执行最多创建一个写入兜底结果框。
- 漂浮窗切换样式、关闭、应用退出时不能遗留动画计时器或捕获已销毁控件的回调。
- 失败原因可以进入诊断日志，但日志不得记录完整识别文本、完整最终输出或目标窗口中的隐私内容。

## 测试策略

### 纯逻辑与配置

- B/C 标识规范化、全局默认和无效值回退。
- 功能 `inherit`、B、C 覆盖解析。
- 旧 JSON 缺少字段时迁移为 B、`inherit` 和兜底开启。
- 保存并重新读取后，中文、其它设置和未知兼容字段不丢失。
- 写入兜底开关与画布节点级设置互不污染。

### 漂浮窗行为

- B 录音状态包含叉号、波形和对号，处理中切换为正确单行状态。
- C 同时区分已确认与临时文字，长文字有限高且跟随最新内容。
- B/C 的取消、结束录音、拖动保存和自动收起回调各触发一次；进入转录后录音动作被清空，迟到或重复点击没有副作用。
- C 在无流式能力、流式中断和无文字时正确降级。
- 样式覆盖只影响对应功能；跟随全局能在全局设置变化后生效。

### 写入兜底

- 缺少目标窗口、目标窗口失效、激活失败、剪贴板不可用和输入注入失败分别触发一个结果小框。
- 兜底关闭时保留可诊断失败，但不弹结果小框。
- 成功写入、用户取消、识别失败和 AI 失败不触发结果小框。
- 已有显式结果小框覆盖时不重复弹窗。
- 兜底结果小框收到完整最终文本，所有既有操作仍可用。

### 可用性与交付

- 使用真实 Qt Widget 截图检查 B/C 的录音、处理中、完成、失败和长文字状态。
- 在普通窗口、最大化、100%、125%、150% 缩放和放大字体下检查中文不裁切、按钮不重叠、卡片不超出屏幕。
- Qt 5.9、MinGW、C++11 Release 构建通过；全量自动化测试通过。
- 可运行目录带齐 Qt 和 MinGW 运行库，并以独立环境启动验证。

## 验收标准

- 用户能在全局设置中点击选择 B 或 C，并立即预览真实样式。
- 新旧用户默认看到 B；每个自定义功能能跟随全局或固定选择 B/C。
- B 在录音时显示取消、波形和完成操作，处理中保持简洁状态。
- C 能显示已确认和临时文字，且临时文字不被提前写入目标窗口。
- 自动写入成功时不出现结果小框。
- 默认配置下，缺少有效外部目标，或本地确认激活、剪贴板、输入注入失败时，只弹出一个包含完整结果的结果小框。
- 用户取消、识别失败和 AI 失败不会被误报为写入失败。
- 旧配置无需手工迁移，现有快捷键、输出方式、画布草稿和流式识别继续工作。

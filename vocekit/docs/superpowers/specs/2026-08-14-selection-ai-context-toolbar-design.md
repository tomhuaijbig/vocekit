# 选中文字 AI 上下文工具条设计

## 1. 背景

用户希望在 Windows 任意支持文本选择的程序中，用鼠标或键盘选中文字后，自动在选区附近显示类似豆包的横向工具条。工具条提供：

- AI 搜索；
- 翻译；
- 解释；
- 保存；
- 复制。

点击需要生成内容的动作后，在工具条下方展开独立结果卡，并支持流式输出、取消、复制、替换、固定和继续追问。

项目已有以下基础能力：

- `SelectedTextReader`：Windows UI Automation 选中文字，强力模式下可用模拟复制兜底并恢复剪贴板；
- `SelectedTextWorkflowController`：选中文字工作流及缺失输入处理；
- 模型请求与流式回调；
- 词库存储、剪贴板写入和替换选中；
- 悬浮窗、结果小框、取消和执行代际隔离的既有实现经验。

本功能不是另写一套 AI 执行系统。核心新增范围是：可靠发现一次选区、取得选区几何信息、在外部程序上方显示不抢焦点的上下文工具条，以及接入联网搜索来源。

## 2. 设计目标

1. 用户完成有效文本选择后约 200–400 毫秒内显示工具条。
2. 点击工具条不取消原选区、不把输入焦点从目标程序永久抢走。
3. 浏览器、记事本、Office/WPS、常见 PDF 阅读器和 Electron 程序具备实用兼容性。
4. 普通模式不操作剪贴板；强力模式必须由用户主动开启。
5. AI 动作支持流式结果、取消、代际隔离和清晰的错误状态。
6. 联网搜索必须显示真实来源；失败时明确降级，不能伪装成联网结果。
7. 密码框、敏感控件和受权限保护的窗口不得读取。
8. 完整选中文字、搜索词和 AI 结果不得进入运行日志。
9. 100%、125%、150%、200% 缩放、多显示器和长中文状态不裁切、不越界。

## 3. 非目标

第一版不处理：

- 富文本格式、图片或表格结构，只传纯文字；
- 对所有 Windows 程序保证 100% 自动发现选区；
- 绕过管理员权限、UIPI、安全桌面或密码控件保护；
- 默认监听剪贴板来推断选区；
- 默认模拟 `Ctrl+C`；
- 自建互联网搜索索引；
- 在第一阶段同时完成联网搜索 Provider。

## 4. 已确认的产品决策

### 4.1 触发方式

采用混合触发：

- 主方式：鼠标拖选完成或键盘选区完成后自动弹出；
- 兜底方式：全局快捷键主动唤起；
- 用户可暂停自动弹出；
- 用户可按应用配置黑名单。

### 4.2 界面形式

采用方案 A：横向工具条与独立结果卡。

- 工具条贴近选区显示；
- 点击 AI 搜索、翻译或解释后，在工具条下方展开结果卡；
- 结果卡与工具条可以分别调整位置以避免屏幕越界；
- 结果卡支持固定；
- 未固定时，选区变化或点击空白处自动关闭；
- 固定后脱离选区生命周期，继续保留用于对照、复制和追问。

### 4.3 AI 搜索

AI 搜索是真正的联网检索：

1. 根据选中文字查询搜索服务；
2. 取得若干网页结果；
3. 由大模型结合搜索结果生成摘要；
4. 在结果卡中展示来源标题、网站和可点击链接。

搜索服务未配置或执行失败时，可以降级为普通 AI 解答，但界面必须明确显示“未进行联网搜索，已使用普通 AI 解答”。这只表示未执行网页搜索，不表示普通模型请求一定在本地运行；首次发送选中文字前仍须经过数据传输授权。

## 5. 总体架构

```text
鼠标/键盘选区事件
  -> SelectionObserver
  -> SelectionProbe
  -> SelectionContextCoordinator
  -> SelectionContextToolbar
  -> SelectionActionRouter
       -> 复制 / 保存（本地）
       -> 翻译 / 解释（已有模型执行链）
       -> AI 搜索（新增 Search Provider + 已有模型执行链）
  -> SelectionResultCard
```

### 5.1 `SelectionObserver`

职责：发现“用户可能刚完成一次选择”，但不直接运行 AI。

- 监听全局鼠标左键释放；
- 监听可能完成键盘选择的按键释放，例如 Shift、方向键、Home、End、PageUp、PageDown；
- 对高频输入做 120–220 毫秒去抖；
- 记录前台窗口、鼠标位置和观察代际；
- 排除 vocekit 自身窗口、工具条窗口、结果卡窗口和明确黑名单程序；
- 应用退出、暂停、锁屏或安全桌面切换时停止观察。

全局钩子回调只采集最小事件信息，不执行 COM、剪贴板或网络操作。后续工作切回 Qt 主线程或专用任务线程。

### 5.2 `SelectionProbe`

职责：读取一次不可变的选区快照。

建议返回：

```text
SelectionSnapshot
  generation
  text
  selectionRects[]
  anchorRect
  cursorPosition
  targetWindow
  targetProcessId
  targetExecutable
  acquisitionMethod
  sensitivity
```

读取顺序：

1. 通过 Windows UI Automation 获取焦点元素；
2. 取得 `TextPattern.GetSelection()`；
3. 读取纯文字；
4. 调用 `GetBoundingRectangles()` 取得一个或多个选区矩形；
5. 过滤空矩形、异常坐标和屏幕外坐标；
6. 将最后一行或最靠近鼠标的矩形选为 `anchorRect`；
7. UI Automation 读取文字失败且用户启用强力选中时，才使用现有模拟复制兜底；
8. 强力模式只取得文字时，以鼠标位置作为几何兜底。

现有 `SelectedTextReader` 应扩展为能够返回结构化结果，而不是在 UI 层再实现第二套 UI Automation。

### 5.3 `SelectionContextCoordinator`

职责：控制一次上下文工具条会话的生命周期。

- 接收 `SelectionSnapshot`；
- 对相同窗口、相同文本和近似矩形的重复观察去重；
- 分配单调递增 `generation`；
- 新选区到来时取消旧的未固定会话；
- 前台窗口、目标窗口或选区代际变化时拒绝迟到结果；
- 固定卡片转移到独立生命周期，不再由新选区关闭；
- 控制最多一个活动未固定工具条和有限数量的固定结果卡。

### 5.4 `SelectionContextToolbar`

新增专用窗口，不直接复用录音状态悬浮条的业务状态。

窗口属性：

- `Qt::Tool`；
- 无边框、置顶、透明背景；
- 尽量使用 `Qt::WindowDoesNotAcceptFocus` 和 `Qt::WA_ShowWithoutActivating`；
- 按钮提供清晰 hover、pressed、disabled 和 busy 状态；
- 不允许整个工具条的拖动过滤器吞掉按钮点击；
- 提供键盘兜底时可选择进入可聚焦模式。

默认按钮顺序：

```text
拖动柄 | 标识 | AI 搜索 | 翻译 | 解释 | 保存 | 复制 | 更多
```

“更多”用于承载自定义功能、替换选中、暂停本站/应用、设置等低频动作，防止横向工具条过宽。

位置算法：

1. 首选放在 `anchorRect` 下方，水平居中；
2. 下方空间不足时放到上方；
3. 仍不足时贴近鼠标并避开鼠标热点；
4. 按目标显示器的 available geometry 裁剪；
5. 使用 Qt 逻辑坐标与 Windows 物理坐标之间的明确转换；
6. 多矩形选区不得用所有矩形的巨大联合区域直接定位。

### 5.5 `SelectionActionRouter`

工具条只发出动作 ID 和不可变快照，不直接依赖模型、词库或剪贴板实现。

动作映射：

- `copy`：现有剪贴板写入；
- `save`：现有词库存储，必要时进入既有快速加入决策；
- `translate`：调用现有翻译功能或专用提示词；
- `explain`：调用现有模型执行链；
- `ai_search`：调用搜索 Provider，再调用模型整合；
- 自定义动作：调用已有功能目录，输入固定为本次 `SelectionSnapshot.text`。

所有异步动作都携带：

- 会话 ID；
- generation；
- 动作 ID；
- 取消令牌；
- 隐私与网络策略快照。

### 5.6 `SelectionResultCard`

结果卡是工具条下方的独立窗口，包含：

- 动作标题和状态；
- 已提交文字与流式临时文字；
- 取消、重新生成、复制、替换、固定、关闭；
- AI 搜索来源列表；
- 错误或降级说明；
- 可选的继续追问输入区。

长内容使用有界窗口和内部滚动，不通过固定高度裁切 `QLabel`。流式更新应节流，避免每个 token 都触发布局和窗口重新定位。

### 5.7 `SearchProvider`

新增抽象接口，避免把 UI 绑定到单一厂商：

```text
SearchRequest
  query
  locale
  resultLimit
  timeoutMs
  networkPolicy

SearchResult
  title
  url
  siteName
  snippet
  publishedAt (optional)
```

要求：

- Provider 配置、密钥和 Base URL 进入现有 SecretStore/设置体系；
- 结果 URL 必须是可验证的 HTTP(S) URL；
- 模型摘要只能引用本次 Provider 返回的来源；
- UI 不得把模型自行生成的 URL 当作已检索来源；
- 设置总超时、结果条数、响应体大小和并发上限；
- 搜索失败与模型失败分开显示和记录错误码。

## 6. 状态机

```text
Idle
  -> Observing
  -> Probing
  -> ToolbarVisible
  -> ActionStarting
  -> Streaming
  -> Completed
  -> Pinned
```

可能的终止路径：

```text
任意未固定状态
  -> SelectionChanged / ForegroundChanged / Cancelled / Closed
  -> Disposed
```

关键约束：

- 一次动作只能产生一个终态；
- `cancel` 后不得再触发 completed 或覆盖结果；
- 新 generation 到来后，旧 generation 的回调一律丢弃；
- 固定卡片必须复制完成时所需数据，不持有已销毁选区会话的裸指针；
- UI 回调允许同步关闭窗口，所有继续访问 `this` 的路径必须使用安全生命周期保护。

## 7. 自动关闭与固定规则

未固定时：

- 选区消失或变化：关闭并取消活动请求；
- 前台窗口变化：关闭；
- 用户点击与工具条无关的空白区域：关闭；
- 按 Esc：关闭；
- 点击另一个动作：取消旧动作并启动新动作，或按产品策略明确并行；第一版采用单动作串行。

固定后：

- 不因选区或前台窗口变化关闭；
- 保留来源、输入摘要和结果；
- 不再允许“替换原选区”，除非能重新确认原目标窗口和选区仍有效；
- 用户可手动关闭或取消固定。

## 8. 安全与隐私

以下规则不可绕过：

1. Password、受保护或安全输入控件不读取、不弹工具条。
2. Windows 安全桌面、锁屏、UAC 页面不处理。
3. 普通权限进程无法读取管理员窗口时，不自动提权、不绕过，仅给出权限说明。
4. vocekit 自身窗口默认排除，避免递归弹出。
5. 完整选中文字、搜索查询、网页正文和模型结果不写运行日志。
6. 日志只允许动作 ID、Provider ID、文本长度、耗时、状态码和取消原因。
7. 第一次使用网络动作时明确提示内容会发送给配置的服务。
8. 复制、保存等本地动作不得隐式触发网络请求。
9. 强力选中必须显式开启，并完整保存和恢复剪贴板的多格式内容。
10. 提供全局暂停、应用黑名单及托盘快速开关。

## 9. 异常和降级策略

| 场景 | 行为 |
| --- | --- |
| 没有文字或只有光标 | 静默，不弹出 |
| 文字过短或只含空白 | 静默，不弹出 |
| 文字成功、矩形失败 | 显示在鼠标附近 |
| 普通读取失败、强力模式关闭 | 静默，保留快捷键兜底 |
| 普通读取失败、强力模式开启 | 临时复制读取并恢复剪贴板 |
| 权限不足 | 不绕过；快捷键触发时显示一次明确提示 |
| 搜索未配置 | 标注降级为普通 AI 解答 |
| 搜索失败 | 保留错误与重试，不伪造来源 |
| 模型失败 | 保留搜索来源，显示模型错误 |
| 文本超长 | 询问处理全文或截取，禁止静默截断 |
| 连续快速选择 | 取消旧代际，只显示最后稳定选区 |
| 目标窗口退出 | 关闭未固定会话 |

## 10. 设置项

建议新增“选中文字工具条”设置区：

- 启用自动弹出；
- 启用键盘选区检测；
- 强力选中；
- 自动弹出最小文字长度；
- 工具条按钮及顺序；
- 默认搜索 Provider；
- 允许联网动作的首次提示状态；
- 点击空白处自动关闭；
- 允许固定结果卡；
- 应用黑名单；
- 暂停时长；
- 快捷键。

默认值应保守：自动弹出可以在功能发布时由用户主动开启，强力选中默认关闭，联网动作首次明确提示。

## 11. 分阶段实施

### 阶段一：可靠弹出与本地动作

- 实现 `SelectionObserver`；
- 扩展结构化 `SelectionProbe`；
- 实现上下文工具条和定位算法；
- 接入复制、保存；
- 接入暂停、黑名单和快捷键兜底；
- 建立 generation、取消和关闭规则。

### 阶段二：AI 流式结果卡

- 接入翻译、解释和自定义功能；
- 实现独立结果卡；
- 支持流式、取消、复制、替换、固定和继续追问；
- 完成长文本滚动、布局节流和生命周期防护。

第一轮正式开发建议覆盖阶段一和阶段二。

### 阶段三：联网 AI 搜索

- 建立 Search Provider 接口和至少一个实现；
- 设置与密钥管理；
- 来源卡片、链接打开和降级提示；
- 搜索与模型错误分层；
- 隐私提示、超时和内容边界。

### 阶段四：兼容与安全加固

- 浏览器、Office/WPS、PDF、Electron 兼容矩阵；
- 多屏、高 DPI、任务栏和屏幕边缘；
- 密码框、管理员窗口、自身窗口和黑名单；
- 睡眠恢复、锁屏、程序退出、连续选区压力测试；
- 性能、日志和剪贴板恢复审计。

## 12. 测试策略

### 12.1 单元测试

- 观察事件去抖、重复选区去重；
- 矩形选择、锚点计算、屏幕边缘避让；
- generation 与迟到回调丢弃；
- 关闭、取消、固定状态机；
- 搜索来源 URL 验证和降级分类；
- 敏感控件与黑名单决策；
- 超长文本策略；
- 日志字段白名单。

### 12.2 Qt Widget 测试

- 工具条按钮真实构造、顺序和可访问文本；
- 点击按钮不被拖动过滤器吞掉；
- 结果卡流式更新、取消、固定和关闭；
- 回调中同步关闭窗口不造成 UAF；
- 长中文、英文、错误详情和来源列表不裁切；
- 100%、125%、150%、200% 字体与缩放检查。

### 12.3 Windows 集成测试

- UI Automation 返回选中文字及一个/多个矩形；
- 记事本、浏览器、Word/WPS、PDF 和 Electron 手工兼容矩阵；
- 鼠标选择和 Shift 键盘选择；
- 多显示器和不同缩放比例；
- 强力选中后剪贴板文本、HTML、图片、文件列表等格式恢复；
- 管理员窗口、密码框和自身窗口不读取；
- 快速连续选择、窗口关闭和休眠恢复后无残留钩子或窗口。

### 12.4 网络与隐私测试

- 搜索 Provider 不配置、超时、错误响应和取消；
- 来源唯一、URL 合法且可点击；
- 搜索失败时降级标识真实；
- 日志、历史和崩溃报告不含完整选择文本或完整 AI 结果；
- 无网络的本地动作不创建网络请求。

## 13. 完成标准

第一、二阶段只有同时满足以下条件才视为可交付：

- 稳定选区后约 200–400 毫秒内出现工具条；
- 普通单击、光标移动和软件自身选区不误弹；
- 点击工具条不永久抢焦点、不破坏原选区；
- 获取失败时静默，快捷键兜底可用；
- 强力读取后剪贴板原格式恢复；
- AI 动作可取消，旧请求不能覆盖新结果；
- 固定与自动关闭行为符合本设计；
- 完整输入和结果不进入日志；
- 中文、英文、长文本和高缩放无裁切；
- 关闭功能后不保留全局钩子、隐藏窗口或后台请求；
- 现有语音、截图、功能画布、选中文字快捷键和悬浮条测试不回归。

阶段三还必须满足：

- 来源来自真实 Search Provider 响应；
- 来源链接有效且与摘要对应；
- 未配置联网搜索或搜索失败时明确标注降级；
- 搜索与模型错误可分别诊断；
- 密钥、查询和网页正文不进入日志或安装包。

## 14. 推荐实施结论

采用“UI Automation 主路径 + 强力选中显式兜底 + 快捷键兜底”的混合方案；采用“横向工具条 + 下方独立结果卡”的交互；第一轮实现阶段一和阶段二，联网 AI 搜索作为独立第三阶段接入。

这样能够最大限度复用 vocekit 已有业务链，同时把系统级选区观察、窗口几何和联网搜索三个高风险部分隔离成可独立测试、可降级的模块。

# 选中文字工具条逐项自定义设计

日期：2026-08-14
状态：已完成对话设计确认，等待用户复核书面规格

## 1. 背景

当前“选中文字工具条”设置只允许拖动五个内置动作的顺序：AI 搜索、翻译、解释、保存、复制。动作名称、是否显示和具体行为仍是固定的，因此它只是排序器，不是用户可使用的功能编辑器。

本设计把该区域升级为软件内置的逐项自定义入口。最终用户可以在设置页自行调整每个动作；这些设置会持久化、重启后保留，并在下一次打开工具条时生效。这里的“自定义”不是开发者替用户写死配置，也不是把内置动作改造成任意类型。

## 2. 目标

- 五个内置动作都能单独改显示名称、显示或隐藏、排序并恢复默认。
- AI 搜索、翻译、解释能够分别选择模型和编辑提示词。
- 翻译能够单独设置目标语言。
- 保存始终打开本地词条编辑器，并能设置新词条默认作用范围。
- 复制能够选择“保留原文”或“去除首尾空白”。
- 复制和保存始终走本地路径，任何配置都不能把它们变成模型或网络请求。
- 保持旧配置、已有顺序、首次模型发送同意、长文本确认和结果卡行为兼容。
- 在 Windows 常用字体缩放和长中文名称下保持可用，不出现文字、按钮或开关裁切。

## 3. 非目标

- 不允许改变内置动作的根本类型。例如“复制”不能改成 AI 动作，“AI 搜索”不能改成本地保存动作。
- 不允许永久删除内置动作；不需要时使用隐藏开关。
- 不把现有自定义功能编辑器合并进本区域。经典自定义功能仍显示在“更多”菜单，画布功能仍遵循现有隔离规则。
- 不为 AI 搜索增加真实网页检索、引用或搜索引擎接入。现有“未进行联网搜索”限制继续生效。
- 不改变结果卡的追问、复制结果、替换选区、固定和取消语义。
- 不增加富文本复制、任意文件保存或新的云端数据同步。

## 4. 用户界面

### 4.1 功能列表

设置卡中的“工具条按钮顺序”改名为“工具条功能”。列表保持纵向布局，每个内置动作占一行，包含：

- 拖动柄；
- 当前显示名称；
- 动作类型摘要；
- 显示开关；
- “设置”按钮；
- 展开或收起状态。

用户可继续拖动排序。点击“设置”后在该行下方展开编辑区；一次最多展开一项，避免纵向设置页过长。编辑在软件设置页内完成，不打开网页，也不依赖外部浏览器。

设置卡底部增加“恢复全部默认设置”。每一项的编辑区另有“恢复此项默认设置”。恢复全部需要确认，恢复单项不影响其他动作或全局工具条开关。

### 4.2 通用字段

所有内置动作都有以下字段：

- 显示名称：去除首尾空白；空值表示使用默认名称；最长 24 个字符。
- 在工具条中显示：默认开启。
- 顺序：通过拖动列表设置。
- 恢复默认：恢复该动作的名称、显示状态和专属字段，不改变其他动作。

当工具条总开关开启时，至少保留一个可见内置动作。用户尝试隐藏最后一个可见动作时，界面保持原开关并提示“请至少保留一个工具条功能”；若用户不需要工具条，应关闭上方总开关。

### 4.3 AI 搜索

- 模型：默认“跟随对应内置功能”。AI 搜索沿用问答功能的当前模型；也可从当前支持的模型目录中选择具体模型。
- 提示词：空值使用内置默认提示词；允许恢复默认。
- 显示名称与显示开关使用通用字段。

AI 搜索仍不是实时联网搜索。无论用户如何编辑提示词，执行层都必须附加不可覆盖的限制：不得声称已实时检索、不得编造来源或时效性事实。结果卡继续显示“未进行联网搜索，已使用普通 AI 解答”。

### 4.4 翻译

- 模型：默认“跟随对应内置功能”，即沿用翻译功能的当前模型；也可选择具体模型。
- 提示词：空值使用内置翻译提示词。
- 目标语言：默认“跟随全局目标语言”；可选择预设语言或填写最长 64 个字符的自定义目标语言。
- 显示名称与显示开关使用通用字段。

目标语言只影响选中文字工具条中的翻译动作，不回写软件的全局目标语言。

### 4.5 解释

- 模型：默认“跟随对应内置功能”，即沿用问答功能的当前模型；也可选择具体模型。
- 提示词：空值使用内置解释提示词。
- 显示名称与显示开关使用通用字段。

### 4.6 保存

- 默认作用范围：可选择全局、听写、翻译、问答或当前存在的某个自定义功能。
- 显示名称与显示开关使用通用字段。

点击保存后始终打开现有本地词条编辑器，并把选择的作用范围作为初始值。用户需要在编辑器中确认原词、标准写法和其他字段后才能写入词库。该路径不读取模型配置，不触发首次模型发送同意，也不访问网络。“全部”只是词库页面的筛选范围，不允许作为新词条作用范围。

### 4.7 复制

- 文本处理：
  - 保留原文；
  - 去除首尾空白。
- 显示名称与显示开关使用通用字段。

复制仍只写入本地剪贴板，不调用模型或网络。第一版不提供富文本、Markdown 或自动改写。

## 5. 配置模型与持久化

### 5.1 稳定身份

每个动作继续使用现有固定 ID：

- `ai-search`
- `translate`
- `explain`
- `save`
- `copy`

显示名称不是身份。改名后，工具条显示和日志仍能通过固定 ID 正确路由，不会把动作串到其他功能。

### 5.2 配置结构

保留现有 `selectionContext.actionOrder` 作为唯一顺序来源，并新增按固定 ID 索引的逐项配置。概念结构如下：

```text
SelectionContextActionCustomization
  displayName
  visible
  modelId
  promptOverride
  targetLanguage
  vocabularyScopeId
  copyMode
```

只有适用于当前动作的字段参与界面和执行。执行层不得因为不适用字段存在而改变动作类型。

JSON 继续位于 `selectionContextToolbar` 下：

```json
{
  "selectionContextToolbar": {
    "actionOrder": ["ai-search", "translate", "explain", "save", "copy"],
    "actionCustomizations": {
      "ai-search": {
        "displayName": "AI 搜索",
        "visible": true,
        "modelId": "",
        "promptOverride": ""
      }
    }
  }
}
```

空 `modelId`、`promptOverride`、`displayName` 或翻译 `targetLanguage` 表示继承对应默认值，而不是已保存的空行为。`promptOverride` 非空时替换该动作可编辑的默认功能指令；应用负责生成的选中文字包装、追问上下文、隐私门禁、长文本确认和不可覆盖的安全后缀仍由执行层添加，用户提示词不能替换这些部分。

### 5.3 规范化

- 顺序使用现有动作顺序规范化逻辑：去重、过滤无效 ID，并补齐遗漏的内置 ID。
- 缺少逐项配置时补默认配置。
- 显示名称去除首尾空白并限制为 24 个字符；空值规范为继承默认名称。
- 提示词去除无意义的首尾空白，最大长度为 8000 个字符；空值规范为使用默认提示词。
- 翻译目标语言去除首尾空白并限制为 64 个字符；空值规范为跟随全局值。
- `vocabularyScopeId` 只接受当前词库作用范围目录中的可写范围，并明确排除 `__all`；空值、未知值、已删除的自定义功能或 `__all` 回退 `__global`。
- `copyMode` 只接受 `original`、`trim`；未知值回退 `original`。
- 模型 ID 通过当前模型目录规范化。目录已知的旧 ID 写回规范 ID；当前有效 ID 保持规范形式；无法识别或已下架的具体模型保留原值以供界面标记不可用，不能使用带默认回退的规范化调用把它静默替换成其他模型。用户可手动恢复“跟随对应内置功能”。
- 若所有已知动作都被保存为隐藏，规范化时恢复默认第一个动作可见，确保总开关开启时工具条可用。

### 5.4 旧配置迁移

旧配置没有 `actionCustomizations` 时：

- 原有 `actionOrder` 原样进入规范化；
- 五项逐项配置全部使用默认值；
- 不改变工具条总开关、隐私同意、黑名单、暂停时间等其他设置；
- 保存后写入新结构。

加载和保存不得删除 `selectionContextToolbar` 或根对象中的未知字段，继续遵循现有向前兼容策略。

## 6. 组件边界

### 6.1 配置与规范化

配置层负责默认值、动作字段适用性、规范化、JSON 读写和旧配置迁移。它不创建控件，也不运行模型。

### 6.2 设置界面

设置卡负责：

- 展示五项；
- 排序、展开、开关和字段编辑；
- 单项或全部恢复默认；
- 将完整的类型化设置交给现有保存回调；
- 保存失败时恢复到最后一次持久化成功的快照。

动作行和动作编辑器应作为独立小组件或支持类，避免继续把所有逻辑堆入现有设置卡。设置卡只协调行列表和保存。

### 6.3 工具条

工具条只读取规范化后的顺序、可见状态和显示名称，并生成按钮。隐藏动作不得出现在主行或溢出菜单；经典自定义功能继续由现有“更多”菜单管理。

工具条发出的仍是固定动作 ID，而不是显示名称。

### 6.4 执行层

动作控制器按固定 ID 分派：

- `copy`：应用复制文本处理后写入剪贴板；
- `save`：调用本地词条编辑器适配器，并传入已规范化的默认作用范围；
- 三个 AI 动作：构造包含该动作自定义模型、提示词和目标语言的请求快照。

模型请求构造器负责合并：内置安全规则、用户提示词、所选文字、追问上下文和不可覆盖的 AI 搜索限制。用户提示词不能覆盖隐私同意、长文本确认、网络策略或 AI 搜索真实性约束。

## 7. 数据流

1. 设置页加载并规范化 `SelectionContextSettings`。
2. 用户编辑某一项；设置卡生成完整新快照并调用现有设置保存链。
3. 保存成功后 Hub 状态和持久化 JSON 同步更新；保存失败则设置卡恢复最后成功快照。
4. 工具条下一次显示或设置刷新时读取最新快照，按顺序、可见状态和显示名称重建按钮。
5. 用户点击按钮；工具条发送固定 ID。
6. 动作控制器读取点击时的完整设置快照。
7. 本地动作直接执行；AI 动作经过已有同意、长文本确认和模型运行链，结果继续进入现有结果卡。

设置修改不要求重启软件。已经运行中的模型请求保持启动时的快照，不在中途切换模型或提示词；下一次执行使用新设置。

## 8. 错误处理与安全边界

- 保存失败：显示可诊断但不含敏感内容的错误，恢复最后成功快照，不能只回滚部分控件。
- 最后一个可见动作被关闭：拒绝该次变更并给出明确提示。
- 具体模型已下架：设置行显示不可用状态；执行时返回明确配置错误，不静默切换到错误提供商或其他型号。
- 提示词过长：界面阻止超过 8000 个字符并显示当前计数，不截断后静默保存。
- 词条编辑器适配器不可用：显示可诊断的本地失败状态，不写入词库，也不触发模型兜底。
- 复制失败：沿用现有本地失败反馈，不触发模型兜底。
- 日志只记录动作固定 ID、执行状态和长度等诊断信息，不记录显示名称、提示词、选中文字、模型正文、剪贴板内容或词库正文。
- AI 搜索的非联网说明和不可编造来源限制不可由用户提示词关闭。

## 9. 测试策略

### 9.1 配置与 JSON

- 默认五项配置正确。
- 旧版仅 `actionOrder` 配置迁移后顺序不变、逐项字段为默认值。
- 新配置 Unicode 往返、空字段继承、非法枚举回退和长度限制正确。
- 未知根字段和未知嵌套字段不被删除。
- 所有动作隐藏时规范化恢复一个可见项。
- 旧模型 ID 按模型目录迁移；未知模型不误分派。

### 9.2 设置界面

- 真实控件覆盖每一项的展开、收起、排序、显示开关和动作专属字段。
- 一次只展开一个编辑区。
- 隐藏最后一个可见动作会被拒绝。
- 单项恢复只影响该项；全部恢复影响五项但不影响工具条其他总设置。
- 保存回调捕获完整类型化配置；返回失败后所有相关控件和内部快照一起回滚。
- 长显示名称、长提示词、错误模型和计数提示状态可见。

### 9.3 工具条与执行

- 五项按保存顺序出现且各不重复。
- 隐藏项不出现在主行和溢出菜单，自定义名称正确显示。
- 点击自定义名称按钮仍发送正确固定 ID。
- AI 搜索、翻译、解释分别使用自己的模型和提示词。
- 翻译的独立目标语言不修改全局目标语言。
- AI 搜索始终附加不可覆盖限制并显示非联网说明。
- 复制两种文本处理模式正确，且模型运行器调用次数为零。
- 保存会以所选默认作用范围打开一次本地词条编辑器；`__all`、未知范围和已删除的自定义功能回退全局；模型运行器和网络调用次数为零。
- 首次模型发送同意、长文本确认、取消、追问和旧回调代际门禁不回退。

### 9.4 视觉与集成

- Windows 原生平台验证 100%、125%、150% 字体缩放。
- 覆盖小窗口、最大化窗口、24 字符中文名称、8000 字符提示词、五项全部展开操作过的密集状态。
- 每个标签、输入框、开关和按钮高度不小于真实 `sizeHint`；按钮不使用导致大字体裁切的固定高度。
- 人工查看关键截图，确认中文、下拉项、滚动区域、提示信息无裁切和重叠。
- 运行配置、设置卡、工具条、动作控制器、请求构造器的聚焦测试及相关回归。
- Qt 5.9/MinGW Release 主程序完整构建成功；最终可执行文件来自包含本次改动的提交。

## 10. 验收标准

以下条件同时满足才算完成：

1. 用户能完全在软件设置页内编辑五个内置动作，不依赖网页或开发者手改配置。
2. 所有通用字段和动作专属字段保存后立即生效，重启后保持。
3. 改名不改变动作身份；隐藏、排序、恢复默认行为准确。
4. 三个 AI 动作的模型和提示词互不串用。
5. 保存、复制在任何配置下都没有模型或网络调用。
6. 旧配置无损迁移，其他选中文字工具条设置不被重置。
7. 保存失败、下架模型、最后可见项和超长提示词都有明确且一致的反馈。
8. 100%、125%、150% 缩放和长中文状态通过真实视觉检查。
9. 聚焦测试、相关回归和 Release 主构建全部通过，工作树不包含测试残留进程或误提交构建产物。

## 11. 推荐实施顺序

1. 配置类型、默认值、规范化和 JSON 迁移。
2. 独立动作行与动作编辑器支持组件。
3. 设置卡接线、保存回滚和恢复默认。
4. 工具条可见性与自定义名称。
5. AI 请求的逐项模型、提示词和目标语言。
6. 保存默认作用范围与复制文本处理模式。
7. 聚焦回归、主程序构建和 Windows 多缩放视觉验收。
